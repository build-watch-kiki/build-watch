# Архитектура Build Watch

## Компоненты

```text
Браузер
   │ HTTP
   ▼
Frontend ───────► Backend API ───────► PostgreSQL
                       │                    ▲
                       ├──────► MinIO       │
                       │                    │
                       ▼                    │
                 RabbitMQ: new-photo        │
                       │                    │
                       ▼                    │
                   CV worker                │
                       │                    │
                       ▼                    │
                 RabbitMQ: cv-result        │
                       │                    │
                       ▼                    │
                 Backend worker ────────────┘
```

- **Frontend** предоставляет управление объектами, календарным планом, фотографиями и аналитикой.
- **Backend API** валидирует запросы, хранит файлы в MinIO, данные в PostgreSQL и ставит задачи в RabbitMQ.
- **CV worker** получает событие о новой фотографии, загружает изображение из MinIO и публикует результаты детекции.
- **Backend worker** сохраняет результаты CV и обновляет аналитическое состояние проекта.
- **Init-контейнеры** применяют миграции, загружают справочники и помещают проверенные веса модели в MinIO до запуска зависимых сервисов.
- **PostgreSQL** хранит проекты, этапы, технику, фотографии и рассчитанный прогресс.
- **RabbitMQ** разделяет пользовательские запросы и ресурсоёмкую обработку изображений.
- **MinIO** хранит исходные изображения отдельно от реляционных данных.

## Поток обработки

1. Backend принимает фотографию, извлекает метаданные и загружает объект в MinIO.
2. В очередь `new-photo` отправляется идентификатор фотографии и ссылка на объект.
3. CV worker выполняет инференс и отправляет структурированный результат в `cv-result`.
4. Backend worker сохраняет обнаружения и запускает пересчёт фактического прогресса.
5. Frontend запрашивает обновлённые данные и отображает план-факт и объяснения отклонений.

## Развёртывание и воспроизводимость

Команда из [корневого README](../README.md#запуск) объединяет базовый
`deploy/docker-compose.yaml` и `compose.source.yaml`. Backend, CV и frontend
собираются из каталогов этого репозитория; инфраструктурные образы закреплены
по digest. Compose ждёт успешного завершения `build-watch-init` перед запуском
API и backend worker, а CV стартует после `build-watch-model-init`. Последний
копирует веса `v2`, `v3` и `v4` из настроенного S3, сверяет SHA-256 из
`model-manifest.json` и загружает модели в MinIO. Версию для CV задаёт
`S3__MODEL_VERSION` в `deploy/.env`. PostgreSQL и MinIO используют именованные volumes,
поэтому данные сохраняются при перезапуске контейнеров.

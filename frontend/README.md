# BuildWatch — мониторинг строительной площадки

Интерфейс для выбора объекта, ведения календарного плана, оценки отклонений и просмотра подтверждающих снимков. Использует Vue 3, TypeScript, Vuetify и Pinia.

## Локальный запуск

Нужен Node.js 24 или Node.js 22.18+ с поддержкой запуска TypeScript в тестах.

```sh
npm ci --legacy-peer-deps
```

При необходимости создайте `.env.local` на основе `.env.example`:

```dotenv
API_BASE_URL=/api/
BACKEND_URL=http://localhost:8000
S3_PROXY_TARGET=http://localhost:9000
```

```sh
npm run dev
```

Vite проксирует `/api/` к backend и `/s3/` к MinIO. Браузер использует относительный `API_BASE_URL=/api/`, поэтому адрес интерфейса может быть локальным или публичным. После изменения `.env.local` перезапустите сервер.

В Docker адреса задаются при запуске контейнера через `API_BASE_URL`, `BACKEND_URL` и `S3_PROXY_TARGET`. Если backend подписывает ссылки с другим адресом MinIO, укажите его в `S3_SIGNED_ORIGIN`. После изменения `.env` достаточно пересоздать frontend-контейнер. Прокси `/api/` и `/s3/` позволяет открыть интерфейс через Funnel без отдельного публичного адреса для backend и MinIO. Для нового домена Funnel добавьте его в `FRONTEND_ALLOWED_HOSTS`.

## Проверки

```sh
npm run build
npm run lint
```

Форматирование выбранных изменённых файлов можно проверить командой `npx prettier --check <пути к файлам>`.

## Данные и интеграция

Объекты, справочники и календарный план используют существующий Axios-клиент в `src/store/api.ts`. Методы, адреса и тела запросов к бэкенду сохранены. Поздние ответы загрузки проекта и плана не заменяют данные более нового запроса при переключении объектов. Создание, редактирование и удаление проверяйте на тестовом бэкенде.

Аналитика мониторинга загружается из `/projects/{id}/progress/daily`: сначала компактная история, затем подробности выбранного дня. Плановые этапы из `/projects/{id}/stages/gantt` содержат необязательный объект `actual`, который фронтенд рисует отдельной фактической полосой.

Для своих снимков откройте объект → «Фотографии» / «Журнал наблюдений» → «Загрузить фотографии». Можно выбрать несколько JPEG или PNG до 20 МиБ каждый. Журнал получает настоящие фотографии через существующий API; статус обработки и детекции обновляются автоматически. Для распознавания и суточной аналитики на бэкенде должны работать очередь и обработчик модели. Переключатель «Показать демо» включает локальные иллюстрации отдельно от реальных фотографий.

Внутренний `SnapshotDetection` поддерживает необязательное поле `color?: string | null`. Валидный цвет `#RRGGBB` конкретной детекции имеет приоритет; при отсутствии или ошибке используется стабильный цвет класса из `src/utils/snapshots.ts`. Рамки, подписи и легенда используют один механизм цветов, а объекты по-прежнему подсчитываются по классу. Возможный будущий формат цвета бэкенда следует преобразовывать в адаптере.
